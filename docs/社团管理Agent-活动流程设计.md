## 第一章 活动前：发起 → 双人投票 → 复议 → 老师批复（定稿 2026-08-26）

### 参与角色

| 角色 | 说明 |
|---|---|
| 发起人 | 任意一位管理层（社长 / 副社长，随机 / 轮值） |
| 投票人 | 另外两位管理层 |
| 审批人 | 指导老师（一票否决权） |

### 流程步骤

**1. 发起**
- 发起人填写活动初稿：**时间、地点、活动大致内容**（三项必填；不含分工、无活动名称字段）
- 提交后开始 **36 小时倒计时**

**2. 首次投票（另外两位管理层）**
- 每人一票：赞成 / 拒绝，**无论赞成与否必须填写理由**
- 两票都赞成 → 提交指导老师过目
- 出现拒绝票 → 进入复议期

**3. 复议期（仅一轮）**
- 另外两位管理层重新投票，**无论赞成与否必须填写理由**
- 再次出现拒绝票 → 活动**立即作废**
- 两票都赞成 → 提交指导老师过目

**4. 指导老师批复**
- 老师查看批准请求时，**可同时看到管理层内部讨论结果**：
  - 无复议期 → 两位管理层的赞成意见（含理由）
  - 有复议期 → 首次投票意见（赞成/拒绝 + 理由）与复议期投票意见（含理由）
- 老师动作：
  - **通过** → 进入下一流程（活动中阶段）
  - **否决**（一票否决）→ 活动作废

### 规则汇总

| 规则 | 内容 |
|---|---|
| 超时 | 36 小时倒计时结束仍未集齐两票赞成 → 自动作废（定时任务扫描） |
| 作废触发（三条） | ① 复议期再次出现拒绝票（即时）② 36h 超时（定时任务）③ 老师否决（即时） |
| 作废通知 | 三位管理层（含发起人），附各人意见与理由；**老师不接收** |
| 留痕 | 每次投票（首次/复议，含理由）全部记录流水，老师可查看完整讨论过程 |

### 设计要点（讨论中确立的关键语义）

1. **复议 = 强制决策，不是等待期**：复议必须明确表态（改同意 / 再次拒绝），不能沉默；再次拒绝 → 立即作废。
2. **投票统一必填理由（一套内容）**：无论赞成与否必填理由，首次投票与复议共用同一套表单；理由本身是决策留痕的主体（例：老社长同意理由"该活动此前举办过，经验教训可复用"，浅资历副社长拒绝理由"跨市难度大"）。
3. **发起人不投票**：发起动作已表达意图，不需要"发起人默认赞成票"；投票者 = 两位表态者，判定 = 两票都赞成。
4. **超时作废 + 通知**：作废带"主动通知"副作用，需定时任务扫描（Spring @Scheduled），而非懒判断。

### 技术落点（实现阶段再细化）

- 活动表：`deadline` + 状态（待管理层批复 / 待老师批复 / 企划通过 / 作废）
- 审批流水表：每张票的变迁（谁 / 动作 / 理由 / 时间）
- 消息表：作废通知（收件人 / 内容 / 已读 / 关联活动）
- 老师时间线视图：活动状态 + 审批流水查询

## 第二章 活动中（定稿中）

### 2.1 活动公示：初稿公布 → 问卷 → 讨论 → 正式文件（定稿 2026-08-26）

**流程**：

```
老师通过（初稿获批）
   ↓
① 活动公示：全体社团成员收到活动初稿（时间/地点/大致内容）
   ↓
② 问卷（发起者自定义问题，发起者定截止时间）：
   ├─ 必答：是否感兴趣
   ├─ 自定义题：是否会修车？1天还是2天？过夜有何顾忌？（按活动定制）
   └─ 感兴趣 → 自动进入讨论群；不感兴趣 → 出局
   ↓
③ 讨论（系统内讨论群，仅感兴趣成员可见）：
   ├─ 集思广益：发起人获取信息（修车找谁、天数怎么定、过夜安排）
   └─ 讨论全程留痕
   ↓
④ 发起人综合讨论 → 撰写【正式活动文件】+ 分工
   （不再过目：其他两位已同意且参与讨论）
   ↓
⑤ 进入执行阶段
   └─ 任何阶段可取消：发起人因问卷不感兴趣人数多等原因取消（必填理由）
```

**关键规则**：

| 规则 | 内容 |
|---|---|
| 惩罚机制 | 问卷填"不感兴趣" → 活动确定后**系统限制无法报名/参与**（不进讨论群，不被讨论信息打扰；落点在报名环节） |
| 取消机制 | 发起人可取消活动（必填理由留痕）；无硬阈值，凭问卷结果判断 |
| 正式文件 | 发起人独撰，含分工，不再走审批 |
| 讨论群成员 | = 问卷答"感兴趣"的人，自动入群 |
| **感兴趣 ≠ 参加** | 感兴趣只决定：进讨论群、提供意见/方案（可线上协助）；**参加与否在执行阶段报名时定**，报名不在本环节 |

**技术落点**：

- 动态表单引擎：问卷（发起者自定义问题）与后续执行记录共用一套"管理层定模板、成员填写"的能力
- 讨论群 = WebSocket（首先方案）：
  - `chat_message` 表（活动ID/发送人/内容/时间）
  - 连接管理（会话 Map）+ 握手鉴权（ws 不走 HTTP 过滤器链，握手拦截器里校验 JWT；握手本身是 HTTP Upgrade，建立后升级为 TCP 长连接双向通信）
  - 先落库后广播（留痕必达，重连后拉取补齐）
  - 心跳 + 断线重连（防僵尸连接）
- 备用降级方案：微信群二维码（发起人贴正式文件里）——实现困难时启用

**已确认决策**：正式文件不再过目；惩罚 = 系统限制；问卷有截止时间（发起人定）；WebSocket 首先方案、微信群备用。

### 2.2 分工（定稿 2026-08-26）：职责项模型

- **职责项模型**：正式文件中的分工 = 发起者在表单中逐条定义的**职责项列表**，每项含：职责描述 + 指派成员（可多人）。
  - 例："突发情况 → 联系 a 社长"；"车辆遇到问题 → 联系 b 副社长和 XXX 同学"；"全程摄像记录及资源整理 → c 副社长和 XXX 同学"。
- **分工 ≠ 参加名单**：分工指定的是"负责某事的人"，不是"现场点名"——不参加活动的人（含因时间冲突的管理层）仍可被指派为联系/支持节点；管理层缺席场景天然兼容。
- **正式文件形态**：结构化表单（动态表单引擎：问卷、正式文件、后续执行记录共用"管理层定模板、成员填写"能力），系统内留痕为主。
- **导出能力（可选增强，不阻塞主流程）**：
  - Word：poi-tl 模板渲染（中文无坑）——后续增强项
  - PDF：优先前端打印导出（浏览器另存为），零后端依赖；后端 OpenPDF/iText 需处理中文字体嵌入，暂不做
  - LaTeX：不适用

### 2.3 执行阶段（定稿 2026-08-26）

**① 报名**（正式文件发布后）
- 参加 / 不参加（截止时间发起者定）；"不参加"可勾选**在线协助**，系统提示发起人
- 问卷"不感兴趣"者系统限制报名（惩罚机制落点）

**② 执行**（线下为主）
- 讨论群已关闭（正式文件发布前转只读/快照）
- 活动期间突发沟通走微信自建群（线下）

**③ 签到**（管理层确认制）
- 到场/缺席由管理层标记
- 报名未到 → 管理层确认具体情况：**补签 + 原因** 或 **记缺 + 原因**
- 签到结果作为打分的事实依据

**④ 执行留痕**
- 活动结束后**规定时间内提交**（时限管理层定）
- 动态表单（管理层定义模板：做了什么/遇到什么/结果如何，必填+字数约束）

**⑤ 奖励机制（等级制）**
- 分数来源①：**讨论建议分**——建议被正式文件采纳（发起人撰写时勾选采纳），被采纳者加分
- 分数来源②：**执行留痕分**——管理层打分（评分+评语）；后续演进：agent 建议分 + 管理层打分并列展示
- 等级：累计分数 → 等级区间（表驱动可配），先做荣誉展示，权限影响暂不做
- 打分本身留痕（谁打的/依据哪条记录/评语）

**⑥ 两层结束**
```
执行完成（活动意义上的结束）→ 执行留痕提交截止
   ↓
复盘：agent 生成复盘方案建议 → 管理层整理确认
   ↓
老师过目复盘 → 活动实体结束（归档）
```
