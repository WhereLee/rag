# 社团管理 Agent 项目：设计讨论记录（备用）

> 创建：2026-08-24，与用户讨论产生的社团管理 Agent 设计草案
> 状态：讨论稿，数据层/细节待后续细化
> 背景：毕设《社团活动全流程管理》的延续，聚焦"社团管理"部分做 Agent 化升级；新项目独立成立，RAG 能力作为工具复用（如资料 PDF 的知识检索）

---

## 一、角色划分

| 角色 | 数量 | 职责 |
|---|---|---|
| 社长 | 1 | 管理层，参与活动决策 |
| 副社长 | 2 | 管理层，负责活动（企划/执行轮值） |
| 社员 | 若干 | 参加活动 |

简单概括：**社长与副社长负责活动，社员负责参加**。

## 二、活动分工模式（轮值 + 搭档制）

以 A（社长或副社长）、B、C 为例：
- 每次活动：**一人主企划 + 两人执行**（搭档制：A 或 A+B 企划）
- 角色环节：
  - **企划**：A 或 A+B 负责（构思活动主题/方案）
  - **资源安排**：B 或 B+C 负责（空教室申请、邀请老师莅临指导等）
  - **现场管理**：C 或 C+A 负责（活动现场组织）
- 轮转机制：下轮企划轮换到 B——同一活动内谁企划谁执行是动态的，角色跟着轮次走
- 每次活动留痕：谁负责企划、谁负责执行等（责任可追溯）

## 三、系统边界（重要设计决策）

- **系统管"活动级职责留痕 + 状态流转"，不管执行细节**（执行怎么谈、怎么做私下解决）
- 目的性是管理：记录谁企划、谁执行、活动状态，责任可追溯
- 执行任务分派方式：**企划人分派**（企划人在企划书里指定执行分工），分派细节线下讨论

## 四、留痕数据的用途（两层）

1. **追溯**：历史活动可查（谁企划过什么、执行过什么、状态流转）
2. **企划建议的数据源**（核心亮点）：下一次某成员做企划时，**企划建议 Agent** 基于历次留痕提供建议——历史活动变成"经验库"

## 五、企划建议 Agent

- 定位：轮值企划时，Agent 基于历史活动数据（类型/规模/预算/复盘结论）给出企划建议
- 本质：**历史经验检索（数据）+ LLM 生成（建议）**——与 RAG 同一骨架（检索 + 生成），检索源从"文档"变为"历史活动记录"
- **冷启动两阶段**：
  - 阶段一（无历史）：Agent 基于通用知识生成建议（活动类型清单、预算范围、流程检查项等通用模板）
  - 阶段二（有积累）：切换到数据驱动（历史活动检索 + 复盘结论注入）

## 六、表单质量约束（保证留痕数据质量）

- **强制表单**：管理层填写留存文档，字段必填、限制字数等（防空白）
- **认知补充（关键）**：必填/字数保证"完整性"，保证不了"信息量"——需要**结构化指标字段**（参与人数、预算执行比例、超时/问题清单、现场异常数），复盘 Agent 才能做"好坏判断"而非"文字总结"
- 数据质量信号 = 表单结构化程度

## 七、复盘 Agent（质量信号的来源，闭环的关键）

- 定位：活动结束后，基于表单真实记录自动生成复盘
- 回答"历史活动好坏从哪来"：管理层落实 → 记录真实情况 → 复盘 Agent 生成复盘 → 沉淀为下一次企划建议的数据源
- 复盘输出待定（两条路）：①给管理层看（活动总结报告存档）②提炼成"经验条目"喂给建议 Agent（大概率两个都要，产出格式不同）

## 八、完整闭环（讨论共识）

```
企划（AI 建议 + 人拍板）
  → 分工执行（企划/资源/现场，轮值+搭档）
  → 表单记录（必填/字数/结构化指标，强制质量）
  → 复盘 Agent（基于真实记录生成复盘）
  → 沉淀（复盘/指标进入经验库）
  → 下一次企划建议（数据源）
```

## 九、待定项（后续讨论）

1. 数据模型设计：活动表/角色留痕表/指标字段/复盘条目（用户明确"具体数据怎么安排还需要后面讨论"）
2. 复盘输出形态（报告 vs 经验条目，或两者）
3. 表单字段清单（结构化指标具体有哪些）
4. 建议 Agent 的输入输出格式（已知信息：时间/预算上限/活动类型偏好；输出：主题方向/预算分配/注意事项）
5. 冷启动模板库内容

## 十、与 RAG 项目的关系

- 新项目**独立成立**（CI/测试/部署/评估全套自证）
- RAG 能力作为**工具**复用：数学社等知识型社团的 PDF 资料管理/问答 → 知识检索工具
- 可复用的工程资产：状态机/幂等（活动状态流转）、LangGraph 图模式（活动流程编排）、评估方法论、CI/部署模板
