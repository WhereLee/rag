## 1. 背景与目标

第二轮实现"坏块隔离"后，失败块以 `page_errors` 记录在 `ingest_job.step_detail`（文本形式，无 bbox）。用户诉求：**把损坏部分显式告知用户（第几页、什么类型、什么原因），由用户自决三种恢复路径**：

1. 重试识别 —— 同一块重新走 VLM（适合临时性失败）
2. 上传替代图 —— 源图损坏，用户提供原图/替代图，多模态识别
3. 文字描述 —— 源不可得，用户直接输入文字/概述兜底

设计哲学与既有 HITL（prompt 审批）一致：机器诚实报告、人做最终决策。

## 2. 数据模型

### 2.1 半成品表补列（已建 issue_items，需补 bbox）

```sql
ALTER TABLE issue_items ADD COLUMN IF NOT EXISTS bbox JSONB;
```

现有列：id / job_id / document_id / page_no / block_order / block_type / reason / status(pending) / resolution / created_at / updated_at

### 2.2 ingest_job 加 job_type

```sql
ALTER TABLE ingest_job ADD COLUMN IF NOT EXISTS job_type VARCHAR(20) DEFAULT 'full';
```

- `full`：整篇入库（现有行为）
- `block_retry`：单块重试（worker 分支执行，保持异步）

### 2.3 状态机

```
issue.status: pending → retrying → resolved | failed | skipped
                      ↘ cancelled（文档 replace 软删时批量取消）
```

- 乐观锁流转：`UPDATE ... SET status='retrying' WHERE id=%s AND status='pending' RETURNING *` 保证并发点两次只成功一次。
- resolution 记录用户动作与结果（如 "describe: 用户提供文字描述" / "replace: 替代图识别成功"）。

## 3. API（Python 侧，经网关代理）

| 接口 | 说明 |
|---|---|
| `GET /api/ingest/jobs/{job_id}/issues` | 失败块清单（含人话 reason + bbox 摘要） |
| `POST /api/ingest/issues/{id}/retry` | 提交单块重试（创建 job_type=block_retry 的 mini job，202 异步） |
| `POST /api/ingest/issues/{id}/replace` | 上传替代图（multipart，创建 block_retry job 带替代图，202 异步） |
| `POST /api/ingest/issues/{id}/describe` | 文字描述兜底（JSON body {"text"}，同步；注入检测+长度限制，直接入 chunk） |

全部走网关代理（GET 复用白名单 `/api/ingest`；POST 加显式端点）。

## 4. Worker 分支

`job_type=block_retry` 的执行流程：
1. 读取 issue（job_id → issue_items）
2. 打开原文件（`data/jobs/`）对应页 → 按 issue.bbox 重渲染区域 → VLM 重试（或使用 replace 上传的替代图）
3. 校验输出（复用第二轮校验）
4. 成功 → append chunk（seq=最大+1，不重排现有 chunk）→ issue resolved
5. 失败 → issue failed（不循环重试，人工可再次提交）

describe 路径不走 worker（同步）：
- `detect_document_injection` 拦截 → 拒收
- 长度限制（≤5000 字符）
- append chunk（text 类型）→ issue resolved(resolution="describe")

## 5. 前端（Documents.vue）

任务卡片"损坏清单"标签：点击展开 issue 列表（第 N 页 / block_type / 人话 reason / 状态），每项三个动作按钮：
- 「重试」→ POST retry → 显示 mini job 状态
- 「上传替代图」→ 文件选择 → POST replace
- 「补充说明」→ 弹窗输入文字 → POST describe

## 6. 实施步骤

1. 补表列（issue_items.bbox + ingest_job.job_type）+ 迁移
