## 1. 背景与问题

第一轮完成异步任务化后，暴露了解析管线的三处短板（用户实测 + 代码审计确认）：

| 问题 | 现象（用户视角） | 根因 |
|---|---|---|
| P1 坏页全灭 | 上传 PDF 报 `code=4: Invalid bandwriter header`，整份文档 dead | `pdf_parser` 页级 catch 只兜 VLM 错误，PyMuPDF 渲染异常穿透到 worker |
| P2 图/文本不分块 | 图占比大的页、小图被静默丢弃，无法按内容分派通道 | 页级决策只看字符数 + 整页表格线，无块级坐标切分 |
| P3 无 Markdown 中间表示 | 解析产物是 text/tables/images 三份并列结构，chunker 手工拼装，语义边界靠猜 | 缺乏"块 → 渲染"的解耦 |

**本轮目标：把解析粒度从"页"细化到"块"，坏块隔离、好块照常，并为后续高质量切块打下中间表示基础。** 最终形态：`PDF → 每页块级 JSON → 规则拼装 Markdown → 切块 → 向量入库`（向量入库在管线末端，本轮完全不触及）。

## 2. 目标与非目标

**目标**
1. 页内块化：一页内区分文本块/表格块/图片块（带坐标、类型、顺序）
2. 分级容错：整篇/整页/单块三级失败处理，坏块不拖死好块
3. 块级并发：并行产出各页各块，受并发闸门保护
4. Markdown 渲染器：块数组 → 页 MD → 整篇 MD（纯函数，可重渲染）
5. 与 job/worker 集成：进度细化到块粒度，错误全部进 `step_detail.page_errors`

**非目标（明确不做，防范围蔓延）**
- 不引入新模型（MinerU/深度学习版面模型等重武器）
- 不改 API 契约/向量库结构/评测体系
- 不做跨页表格合并（留作后续；单页多表先按块拆分）
- 不做手写体识别等专用 OCR（现有通道 C 可覆盖）

## 3. 总体设计（五段流水线）

```
上传文件
  ↓
① 块化提取（页级）  get_text("blocks") + get_images + get_drawings  → 坐标块分类 + 冲突裁决  ← 本轮核心改造
  ↓
② 块级并行处理      线程池 + 信号量闸门（VLM 并发上限） → 每块按类型分派（文本直提/表格VLM/图片VLM）
  ↓
③ 结果重排         按 page_no + block.order 重排，缺块留占位记录
  ↓
④ Markdown 渲染    Block[] → 页 MD → 整篇 MD（规则模块，纯函数）
  ↓
⑤ 切块 + 向量入库   使用现有 chunker 消费 MD —— 不动
```

改造范围集中在 `rag-python/src/ingest/` 的 `page_analyzer.py` / `pdf_parser.py`，新增 `block_types.py` + `md_render.py`；`chunker.py` 后续可选改消费 MD（本轮保兼容，不强制改）。

## 4. 详细设计

### 4.1 块协议（新增 `ingest/block_types.py`）

```python
# 块类型枚举
class BlockType(str, Enum):
    TEXT  = "text"
    TABLE = "table"
    IMAGE = "image"

@dataclass
class Block:
    page_no: int          # 0-based 页码（排序锚点）
    order: int            # 页内阅读顺序（0 起）
    type: BlockType       # 类型
    bbox: list[float]     # [x0,y0,x1,y1] 页面坐标（定位/裁剪用）
    text: str = ""        # TEXT 块内容 / TABLE 块 markdown 内容 / IMAGE 块描述文本
    meta: dict = field(default_factory=dict)  # 图片的 text_in_image / 表格来源等
    status: str = "ok"    # ok / failed(render) / failed(validate) / failed(vlm) / unfixable
    error: str = ""       # 失败原因（人话化文案，见 4.4）

@dataclass
class PageResult:         # 页级产出（对外 JSON 结构）
    page_no: int
    page_status: str      # ok / partial / failed
    blocks: list[Block]
    errors: list[dict]    # [{"block_order":N,"kind":"render_failed","detail":"..."}]
```

对外 JSON 形态（用户指定方向）：

```json
{
  "page_no": 3,
  "page_status": "ok",
  "blocks": [
    { "type": "text",  "text": "调研覆盖37家企业…", "order": 0, "bbox": [72,96,522,130] },
    { "type": "table", "text": "|行业|数量|\n|---|---|", "order": 1, "bbox": [72,160,522,220] },
    { "type": "image", "text": "架构图：检索→精排→生成", "meta": {"text_in_image":"…"}, "order": 2, "bbox": [72,240,300,420] }
  ],
  "errors": []
}
```

### 4.2 页内块化算法（`page_analyzer.py` 重构，替代现在的字符数二元判定）

**信息采集（PyMuPDF 原生 API，零成本、可复现）：**

| 候选块 | API | 说明 |
|---|---|---|
| 文本块 | `page.get_text("blocks")` | 每项 (x0,y0,x1,y1,text,block_no,block_type) |
| 图片块 | `page.get_images(full=True)` + `page.get_image_rects` | 每张图片的显示矩形；异常显式记录（不再静默 continue） |
| 表格块 | `page.get_drawings()` 线条聚类 | 复用现有算法，改造点：多区域聚类（按空间邻近分簇）而不是整页一个包围盒 |

**四步算法：**

```
STEP 1 采集 → 三类候选（文本/图片/表格）各带 bbox
STEP 2 冲突裁决（重叠时谁吞谁，按优先级）:
   a. 图片 ⊃ 文本（文字 bbox 完全在图片框内）→ 文字并入图片块（截图内文字）
   b. 表格 ⊃ 文本 → 表格块整体吞并内部文字
   c. 图片与文本的 bbox 重叠但文本不完全在图中 → 文本保留（图注）
   d. 图片与图片重叠 → 按面积保留大图
STEP 3 阅读顺序排序：按 bbox 中心 y 分行（行高容差），行内按 x 排序 → 赋 order（单栏场景；双栏需栏检测，本轮先做单栏，双栏留 TODO 注释）
STEP 4 汇总 PageResult：按块类型标记 status=ok ready 待处理
```

**通道决策（块级替代页级）：**
- 文本块 → 直提（零成本）✅
- 表格块 → 裁剪 bbox → VLM 表格结构化（复用现有 TABLE_PROMPT）
- 图片块 → 裁剪 bbox → VLM 语义描述（复用现有 IMAGE_PROMPT）
- 整页无文本块无图片块（空白页/腰封页）→ 单页跳过（记 page_status=skipped）
- 整页无文本块（纯图页/扫描页，chars<50）→ 整页一个超大图片块 → 走整页 VLM 转录（通道 C 语义保留）✅

**用户核心诉求落地：图 50% + 文 50% 的混合页：**
文本块直提 + 图片块 VLM 并行处理，两路各归各的，互不拖累 —— 正是 P2 的答案。

### 4.3 块级并发（新增 `ingest/parallel.py`，或并入 pdf_parser 内部）

- 线程池：`ThreadPoolExecutor(max_workers=min(4, cpu_count))`，任务粒度 = 块
- 信号量闸门：`BoundedSemaphore(3)` 限制并发 VLM 调用数（MIMO 限流 + 本地 CPU 保护）
- 超时：单块 VLM 超时走现有 `mimo_client` 重试 + 块级退避
- 结果重排缓冲：并发结果按 `(page_no, order)` 排序后落盘，缺块留占位进 errors——保证整篇 MD 页码与块序稳定。

### 4.4 分级容错（核心决策）—— 这是本轮对P1 的完整答案

**三级失败层次：**

| 层级 | 判断 | 任务状态影响 | 重试策略 |
|---|---|---|---|
| 整篇失败 | 文件打不开 / 0 页可解析 | job dead + 错误留档 | 不重试（确定性失败，重了也白费） |
| 整页失败 | 该页渲染/解码全炸（如 `code=4` 一页） | 页 skipped，其余页照常 | 网络类可重试；文件类直接 unfixable 不烧额度 |
| 单块失败 | 单图流损坏 / 表格 VLM 校验不过 | 块 failed 记录，同页其余块照常 | 同上 |

**失败分类函数（`ingest/errors.py`，错误文案人话化映射表）：**

| 原始错误 | 分类 | 对外文案 |
|---|---|---|
| `pymupdf.mupdf.FzErrorArgument: code=4: Invalid bandwriter header dimensions/setup` | unfixable_file | `第N页图片数据损坏，已跳过该图（其余内容正常）。若需修复请重新导出该PDF` |
| VLM 网络错误/超时/429 | retriable | `AI 识别服务暂不可用，自动重试中` |
| VLM 输出校验失败（表格乱编/空转录） | discard_block | `第N页表格识别结果异常，已丢弃该表格（其余内容正常）` |
| 页面无法渲染（其他 PyMuPDF 异常） | unfixable_file | `第N页无法解析，已跳过（文件可能在导出时损坏）` |

**与 job 状态机衔接：**
- 任务最终状态：只要有 ≥1 个可用块 → `done（含 N 个失败块记录）`，而非 dead
- 全部块失败 → `failed`（可重试）或 `dead（unfixable）` 按分类
- 失败块全部进 `step_detail.page_errors` 的 block 级条目（第一轮 JSON 结构中已预留 page_errors，扩展到块级）

### 4.5 Markdown 渲染器（新增 `ingest/md_render.py`，纯函数无副作用）

```python
def render_page(page: PageResult) -> str:      # 块数组 → 页 MD
def render_document(pages: list[PageResult]) -> str:  # 整篇 MD（页间加分隔注释）
```

渲染规则（规则识别模块，用户指定方向）：
- TEXT 块 → 原文段落（保留换行）
- TABLE 块 → 直接嵌入其 markdown 内容
- IMAGE 块 → `![图N：{description}](...可选占位)` + 图内文字引用
- 失败块 → 页内注释 `<!-- 第N块识别失败：原因 -->` 不中断文档流

此模块与解析完全解耦：改渲染规则不需要重跑解析（块 JSON 是源真相），后续切块改消费 MD 即可提升质量。

### 4.6 与 job/worker 集成

- `worker.py` 的 `_make_progress_cb` 回调粒度从"页"细化到"块"：`progress = 0.05 + 0.4 * (已处理块数/总块数)`（解析阶段区间维持 0.05~0.45 不动，兼容前端展示）
- 每块完成即 `update_progress` 一次（已在第一轮实现），块级失败同步写入 step_detail —— 前端任务卡片明细直接可见"哪一页哪一块坏了、为什么"

### 4.7 兼容与迁移

- `parse_pdf` 保留对外签名 `(path, enable_figure_parse, progress_cb) -> (pages, stats)`，内部实现替换为块化流程 —— **API 契约零变化，调用方（sync_service）无需改动**
- stats 扩展字段：`blocks_total / blocks_failed / pages_failed / unfixable`（前端与诊断可消费）
- 旧页面缓存（`data/parsed/{hash}.json`）结构保持兼容：新增键迁移逻辑（v1→v2），旧缓存失效重建走新管线

## 8. 审查修订（2026-08-19 v1.1，编码前自查）

对 v1 方案的审查发现如下问题并修订（方向不变，补强工程细节）：

| # | 问题 | 修订 | 影响章节 |
|---|---|---|---|
| R1 | 块级并发拉长任务耗时，worker 5 分钟租约不续期，处理中任务会被其他 worker 抢走重复执行（SKIP LOCKED 只保护领取瞬时不保护处理期） | worker 每完成一个块即续租（`lease_until=NOW()+lease`），消除长任务的重复处理竞态 | 4.3/4.6 |
| R2 | "≥1 个可用块即 done"过松：百页坏 99 页也算成功，用户感知 100% 成功但内容 99% 丢失 | 完成判定加质量阈值：可用页占比 ≥50%（可配）才 done；低于阈值 → 任务 failed 提示质量差（保留已成功页可检索）；0 可用块 dead | 4.4 |
| R3 | 通道 C 预判（chars<50）与块化顺序未定义，扫描页整页转录语义可能被破坏 | 流程改为：页级预判（chars<50 → 整页图片块走转录 C）→ 有文本页再块化；块化后无文本块判定与预判统一为一个入口 | 4.2 |
| R4 | 缓存迁移表述含糊，"v1→v2 迁移"本不需要 | 缓存键带结构版本后缀（`{hash}.v2.json`），v1 缓存自然作废，无需迁移逻辑 | 4.7 |
| R5 | 错误分类缺兜底方向 | 分类函数默认 retriable（宁可重试也不冤枉文件），未知分类记 unclassified 供观测学习 | 4.4 |
| R6 | 同步路径 ingest_file 仍消费旧 page 结构，缺转换层 | 新增 `to_legacy_page(PageResult) -> dict` adapter，新管线输出统一转回旧结构，sync_service 零改动 | 4.7 |
| R7 | 全量重排后渲染导致大文件整篇驻留内存 | 按页粒度流式：页内块并行完成即渲染该页 MD 输出，内存 O(页块数) 而非 O(整篇) | 4.3/4.5 |

以上修订已并入执行阶段设计，实施以下列修订为准。
