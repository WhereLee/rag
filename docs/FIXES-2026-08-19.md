## 1. 安全漏洞修复：文件上传绕过 Java 网关

### 问题描述
- **原始架构**：前端 → Vite proxy → Python 服务（直连，绕过 Java 网关）
- **安全风险**：前端自行添加 `X-User-Id` 请求头，Python 服务直接信任该值
- **漏洞场景**：恶意用户可伪造 `X-User-Id`，上传文件到其他用户的文档空间，实现越权访问

### 修复方案
采用**方案 A-1：Java 网关做文件上传代理**

#### 1.1 Java 网关添加文件上传代理端点

**文件**：`rag-java/src/main/java/com/rag/gateway/controller/AdminProxyController.java`

**修改内容**：
```java
/**
 * 文件上传代理：验证 JWT 后转发 multipart 请求到 Python 服务。
 * 安全：从 JWT token 提取 user_id（不信任前端传入的 X-User-Id），
 * 确保用户只能上传文件到自己的文档空间。
 */
@PostMapping(value = "/proxy/api/ingest/upload", consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
public ResponseEntity<?> proxyUpload(
        @RequestPart("file") MultipartFile file,
        @RequestParam(value = "replace", required = false, defaultValue = "false") Boolean replace,
        HttpServletRequest req) {
    
    String username = (String) req.getAttribute("username");
    Long userId = userService.getUserIdByUsername(username);
    String requestId = (String) req.getAttribute("X-Request-ID");
    
    long t0 = System.currentTimeMillis();
    try {
        // 构建 multipart 请求体转发给 Python 服务
        MultiValueMap<String, Object> body = new LinkedMultiValueMap<>();
        body.add("file", file.getResource());
        if (replace != null && replace) {
            body.add("replace", "true");
        }
        
        Object resp = python.post()
                .uri("/api/ingest/upload")
                .contentType(MediaType.MULTIPART_FORM_DATA)
                .header("X-User-Id", String.valueOf(userId))
                .header("X-Request-ID", requestId != null ? requestId : "")
                .body(BodyInserters.fromMultipartData(body))
                .retrieve()
                .bodyToMono(Object.class)
                .timeout(Duration.ofMinutes(5))
                .block();
        
        audit.record(username, "upload", "/api/ingest/upload", 200, System.currentTimeMillis() - t0);
        return ResponseEntity.ok(resp);
    } catch (Exception e) {
        audit.record(username, "upload", "/api/ingest/upload", 502, System.currentTimeMillis() - t0);
        return ResponseEntity.status(502).body(Map.of("error", "上传失败: " + e.getMessage()));
    }
}
```

**新增导入**：
```java
import org.springframework.util.LinkedMultiValueMap;
import org.springframework.util.MultiValueMap;
import org.springframework.web.multipart.MultipartFile;
import org.springframework.web.reactive.function.BodyInserters;
```

**文件**：`rag-java/src/main/resources/application.yml`

### 修复后的架构
```

    ↓ multipart/form-data

```

## 2. TXT 文件支持

### 问题描述
- API 层（`ingest_api.py`）的 `ALLOWED_SUFFIXES` 包含 `.txt`
- 但 `sync_service.py` 的 `DOC_TYPES` 和解析路由不包含 `.txt`
- 导致上传 TXT 文件时报错：`不支持的文件类型: .txt`

### 修复方案

#### 2.1 添加 TXT 解析器

**文件**：`rag-python/src/ingest/doc_parser.py`

**新增函数**：
```python
def parse_text(path: Path) -> tuple[list[dict], dict]:
    """解析纯文本文件：将整个文件内容作为单页返回。"""
    text = path.read_text(encoding="utf-8", errors="ignore")
    page = {"page_no": 0, "channel": "TXT", "text": text,
            "tables": [], "images": []}
    stats = {"page_count": 1, "channels": {"TXT": 1},
             "vlm_calls": 0, "figures_parsed": 0, "failed_pages": []}
    return [page], stats
```

#### 2.2 更新 sync_service.py

**文件**：`rag-python/src/ingest/sync_service.py`

**修改 1 - 导入**：
```python
from ingest.doc_parser import parse_markdown, parse_image_file, parse_docx, parse_text, IMAGE_EXTS
```

**修改 2 - DOC_TYPES 映射**：
```python
DOC_TYPES = {".pdf": "pdf", ".md": "markdown", ".docx": "word", ".txt": "text"}
```

**修改 3 - 解析路由**：
```python
if suffix == ".pdf":
    pages, stats = parse_pdf(path)
elif suffix == ".md":
    pages, stats = parse_markdown(path)
elif suffix == ".docx":
    pages, stats = parse_docx(path)
elif suffix in IMAGE_EXTS:
    pages, stats = parse_image_file(path)
elif suffix == ".txt":
    pages, stats = parse_text(path)
else:
    raise ValueError(f"不支持的文件类型: {suffix}")
```

### 验证结果
✅ TXT 文件上传成功，正确显示类型为 "text"

## 3. Windows 文件锁定问题

### 问题描述
- Windows 上 PDF 解析器（PyMuPDF）可能仍持有临时文件句柄
- 调用 `tmp_path.unlink(missing_ok=True)` 时报错：`PermissionError: [WinError 32] 另一个程序正在使用此文件，进程无法访问`
- 导致上传失败（500 错误）

### 修复方案

**文件**：`rag-python/src/api/ingest_api.py`

**修改内容**：
```python
finally:
    # Windows 文件锁：PDF 解析器可能仍持有句柄，延迟重试删除
    import time
    for attempt in range(3):
        try:
            tmp_path.unlink(missing_ok=True)
            break
        except PermissionError:
            if attempt < 2:
                time.sleep(0.1)  # 等待 100ms 后重试
            else:
                # 最终失败：记录警告但不影响主流程
                import logging
                logging.getLogger("rag.upload").warning(
                    f"无法删除临时文件 {tmp_path}，文件被占用")
```

### 设计思路
- 重试机制：最多重试 3 次，每次间隔 100ms
- 降级处理：最终失败时记录警告日志，但不影响上传成功
- 临时文件会在系统重启或磁盘清理时被清理

### 验证结果
✅ 文件锁定问题修复，临时文件删除失败不再导致上传失败

## 4. PDF 解析器类型错误

### 问题描述
- `pdf_parser.py` 第 51 行尝试对 `region.rect` 做坐标扩展：`clip = region.rect + (-2, -2, 2, 2)`
- `region.rect` 可能是 `pymupdf.Rect` 对象或普通 Python 列表 `[x0, y0, x1, y1]`
- 当 `region.rect` 是列表时，`列表 + 元组` 报错：`TypeError: can only concatenate list (not "str") to list`

### 修复方案

**文件**：`rag-python/src/ingest/pdf_parser.py`

**修改内容**：
```python
# 通道 B：表格区域逐个 VLM 结构化
for region in analysis.table_regions:
    # 确保 rect 是 pymupdf.Rect 对象
    rect = region.rect if isinstance(region.rect, pymupdf.Rect) else pymupdf.Rect(region.rect)
    clip = rect + (-2, -2, 2, 2)  # 略放大防切边
    clip = clip & page.rect
    png = _render_png(page, clip=clip)
    md = vlm.parse_table_region(png)
    stats["vlm_calls"] += 1
    if md:
        page_repr["tables"].append(md)
```

### 设计思路
- 类型检查：使用 `isinstance()` 检查 `region.rect` 的类型
- 类型转换：如果是列表，转换为 `pymupdf.Rect` 对象
- 安全操作：确保 `+` 运算符用于相同类型

### 验证结果
✅ PDF 解析器直接测试成功，返回 21 页，279 个 chunks

## 5. VLM 多模态消息类型错误

### 问题描述
- `vlm.py` 发送多模态消息时 `content` 是列表（包含文本和图像）：
  ```python
  messages = [{
      "role": "user",
      "content": [
          {"type": "text", "text": prompt},
          {"type": "image_url", "image_url": {"url": _img_to_data_url(png_bytes)}},
      ],
  }]
  ```
- `mimo_client.py` 第 83-84 行假设 `content` 是字符串：
  ```python
  last_msg = messages[-1].get("content", "")
  prompt_summary = last_msg[:200] + ("..." if len(last_msg) > 200 else "")
  ```
- 当 `content` 是列表时，`last_msg[:200]` 返回列表，`列表 + "..."` 报错

### 修复方案

**文件**：`rag-python/src/llm/mimo_client.py`

**修改内容**：
```python
# 日志：记录 prompt 摘要（仅前 200 字符，避免泄露敏感内容）
prompt_summary = ""
if messages:
    last_msg = messages[-1].get("content", "")
    # 处理多模态消息（content 可能是列表）
    if isinstance(last_msg, list):
        # 提取文本部分
        text_parts = [item.get("text", "") for item in last_msg if isinstance(item, dict) and item.get("type") == "text"]
        last_msg = " ".join(text_parts)
    if isinstance(last_msg, str):
        prompt_summary = last_msg[:200] + ("..." if len(last_msg) > 200 else "")
    else:
        prompt_summary = str(last_msg)[:200]
```

### 设计思路
- 类型检查：使用 `isinstance()` 检查 `last_msg` 是列表还是字符串
- 列表处理：如果是列表，提取所有 `type="text"` 的项并拼接
- 字符串处理：如果是字符串，直接截取前 200 字符
- 兜底处理：其他类型转换为字符串

### 验证结果
✅ TypeError 修复，VLM 调用正常工作

except Exception as e:
